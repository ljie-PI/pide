1. 键位作用域边界（绝不污染原生 Vim 操作符） 规格 §18.3, §19.7

Buffer 类型允许的键位形式禁止事项与原因
可编辑代码 / Diff Buffer仅注册 <leader>a… 前缀命令（如 ac 评论、as 发送、ad Diff、ab 切新旧侧、ai 聚焦输入）与窗口跳转 <C-w>h/j/k/l严禁占用 c/C（修改）、r（替换）、gd（跳定义）、gt（切 Tab）、gq/gw（排版）
pide 只读插件 Buffer / 浮窗Buffer-local 短键：j/k 移动、Enter 执行、Space 勾选、p 预览、t 发送目标/新 Tab、S 紧急插话发送、r 解决或撤回、d 忽略、q/Esc 栈式返回所有浮窗（模型、发送目标、工作区、提问）均完整支持纯键盘闭环

2. 评论派生生命周期与严格状态动作表 规格 §8.2–8.6

草稿 (draft) ──发送──▶ 已排队 (sent+queued) ──轮到执行──▶ 处理中 (sent+running) ──收到关联回复──▶ 待确认 (sent+reply) ──▶ 已解决 (resolved)
   │                        │ (撤回/Stop/Compact)                                                           │                     │
   └──忽略──▶ 已忽略         └────────────── 统一回退为「草稿」并还原文字+引用                               └──继续追问            └──重开 (保留历史)
派生展示状态允许动作（禁止跨状态误标“解决”）
草稿 / 已忽略草稿：发送、编辑、忽略；已忽略：恢复为草稿
已排队 / 处理中已排队：撤回编辑（回退草稿）；处理中：查看目标会话（未回复前不伪造“待确认”）
待确认 / 已解决待确认：解决、要求继续修改；已解决：重开（保留上下文与历史回复）

3. 双侧 Diff 与窄屏单栏 Base ⇄ Modified 切换 规格 §8.1, §19.4

场景精确窗口行为
宽屏 Diff ReviewBase (可定位评论) | Modified (可定位评论) | 右侧复用 Dock 切到 Review 页（严格最多三栏）；评论携带 side: base | modified
窄屏单栏 Diff窄屏不是禁用 Base：单栏顶栏提供 Base 旧侧 ⇄ Modified 新侧 切换（及 <leader>ab）；在底部 Shelf 选中 Base 评论时单栏自动切到 Base 并定位上下文，选回 Modified 评论再自动切回 Modified

4. 跨断点边沿响应式迁移与返回栈 规格 §19.4–19.5, §19.7

机制防抖与所有权规则
仅跨越断点才迁移记录 reviewLastNarrow：同一断点内继续缩放或开关导航栏时，尊重用户手动改过的 Dock / Shelf 开闭状态，绝不强行重开被隐藏的 Dock
区分自动与手动 Shelf记录 shelfAutoOpenedByNarrow：从窄屏拉回宽屏时，只收起窄屏自动展开的 Shelf（用户主动打开的 Shelf 原样保留），彻底杜绝双评论面板
栈式返回退出 Review 精确恢复进入前的 Dock 页签与开闭状态；从 Tree → Merge 按 q 优先退回 Tree

6. 统一运行中默认队列、多目标与低频评论 Steer 规格 §7.2, §8.3, §9.2, §21

入口统一心智模型
运行中默认发送代码区（<leader>as 弹单行提问框即发并留代码区）与 Chat 输入框（<Enter>）统一默认 Follow-up；Steer 统一作为显式次级动作（<leader>aS / <Alt+Enter>）
单条与批量目标防串台行内单条评论固定发给当前活跃会话（写明会话名，不继承批量目标）；评论架批量发送显示 发送已勾选 (N) → 目标（N = 0 禁发）；并行子代理结果直接接入合并页且 0 来源禁止创建新会话
工作区隔离与非抢占提问每个 Workspace 独立持有评论、多会话列表与各自队列（切换互不串台、后台任务不断）；AI 普通提问先在状态栏/Dock 非抢占提示，按 <leader>ar 或点击才开对比浮窗
