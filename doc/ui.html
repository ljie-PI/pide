pide.nvim Neovim 交互规格原型
闭环 1：打开独立 Thread 主会话 主区域宽版
正常打开文件 → Spaceai 打开当前 Thread buffer（没有则新建）→ 在主区域阅读与输入 → Tab 切换 Thread，q 返回代码
闭环 2：代码评论与分批投递 下划线锚点
Spaceac 打开评论小窗直接编辑（已有评论则直接编辑）→ 侧栏勾选一批发往 Thread A → 再勾选剩余草稿发往 Thread B 或新 Thread
闭环 3：Fork、Skill 拆分与公共前缀 Merge 真实谱系
Thread 内 f Fork / s 拆分 skill → 记录 parentId 与 entry lineage → m 选择多个 Threads 合并；公共前缀只继承一次，无祖先则 handoff

1. 键位作用域边界（绝不污染原生 Vim 操作符） 规格 §18.3, §19.7

Buffer 类型允许的键位形式禁止事项与原因
可编辑代码 / Diff Buffer仅注册 <leader>a… 前缀命令（如 ac 评论小窗新建/编辑、av 打开当前行关联 Thread、ai 打开 Thread、as 发送、ad Diff、ab 切新旧侧）；窗口跳转沿用原生 <C-w>h/j/k/l，pide 不新增、不改写任何窗口键严禁占用 c/C（修改）、r（替换）、gd（跳定义）、gt（切 Tab）、gq/gw（排版）

3. 双侧 Diff、统一 Comment 与现有重定位规则 规格 §8.1–8.5, §19.4

场景精确窗口行为
宽屏 Diff ReviewBase (可定位评论) | Modified (可定位评论) | 右侧复用 Dock 评论页（严格最多三栏）；评论携带 side: base | modified
窄屏单栏 Diff窄屏不是禁用 Base：单栏顶栏提供 Base 旧侧 ⇄ Modified 新侧 切换（及 <leader>ab）；在底部 Shelf 选中 Base 评论时单栏自动切到 Base 并定位上下文，选回 Modified 评论再自动切回 Modified
统一 Comment 模型普通文件与 Diff 共用同一评论数据、草稿、发送、队列与回复链接；Diff 只增加 side、固定 base_ref 和可选 hunk 归属，Base 锚定固定 commit
quote/hash 与 outdated沿用现有创建时快照、内容 hash 与 text quote；原文可唯一定位时更新行号并标记 moved，原文不存在、匹配不唯一或文件删除时标记 outdated 并保留快照，发送前重新计算定位，不新增锚点系统

4. 跨断点边沿响应式迁移与返回栈 规格 §19.4–19.5, §19.7

机制防抖与所有权规则
仅跨越断点才迁移记录 reviewLastNarrow：同一断点内继续缩放或开关导航栏时，尊重用户手动改过的 Dock / Shelf 开闭状态，绝不强行重开被隐藏的 Dock
区分自动与手动 Shelf记录 shelfAutoOpenedByNarrow：从窄屏拉回宽屏时，只收起窄屏自动展开的 Shelf（用户主动打开的 Shelf 原样保留），彻底杜绝双评论面板
栈式返回退出 Review 精确恢复进入前的 Dock 状态；Space ai 将 Thread buffer 推入主区域并隐藏评论侧栏，按 q 返回原代码/Diff 与面板状态；从 Tree → Merge 按 q 优先退回 Tree

5. 统一队列排空回滚与系统通道隔离 规格 §7.2, §8.3, §9.3

withdrawQueueItem() / stopRunningThread() / runCompact() / submitComposer("interrupt")
  └── 共用 rollbackQueuedItemsToDraft(items):
        1. 合并还原未消费文字 + 去重保留全部引用/附件 (refs)
        2. 将关联未消费评论持久化状态统一回退为 draft（杜绝 Compact 后出现假「处理中」）
        3. 独立保留 queue.system（后台子代理与后台命令完成通知绝不丢失）

6. Thread、评论目标与谱系 Merge 规格 §7.2, §8.3, §9, §21

入口统一心智模型
Thread 主视图<leader>ai 打开当前 Thread buffer（没有则创建），在主区域显示完整 transcript、Plan、队列和输入框；Tab 切换 Thread，q 栈式返回代码
评论编辑与分批投递代码/Diff 中 <leader>ac 直接打开评论小窗新建或编辑当前行草稿，无单条“发送到当前 Thread”或“编辑”按钮；所有发送统一通过侧栏/Shelf 勾选一批投递到当前、指定或新 Thread，N = 0 禁发
运行中发送与撤回空闲立即发送，运行中默认 Follow-up，显式选择才 Steer；发送不是填入输入框等待，撤回未消费项统一在 Thread/Queue 完成并回滚草稿
Fork 与 Skill 拆分Thread 内 f 显式 Fork，s 通过拆分 skill 创建子 Threads；记录 parentId、forkEntryId 与 entry lineage，不再需要独立“任务”页
公共前缀 Merge仅对真实公共祖先继承一次并合并分叉后缀；Pi append-only entry tree 与 fork 提供谱系优势，但跨独立 Threads 仍由 pide 执行 handoff merge，不伪造公共前缀
